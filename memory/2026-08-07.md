## Incident: Honcho add_messages 500 Error

**Reported by:** Bob (via Pieter)
**Status:** ✅ RESOLVED

### Root Cause

`honcho-api-1` container on honcho-m1 was missing `LLM_OPENAI_API_KEY` in its environment. The embedding client (`text-embedding-3-small` via OpenRouter) requires this var to initialize. Health endpoint and reads don't trigger the embedding path — only writes (`add_messages`) do.

Error in container logs:
```
ValueError: OpenAI API key is required
```

### Fix Applied

1. Created Hetzner snapshot: `pre-honcho-addmessages-fix-2026-08-07-1048` (ID: 417407465) — validated `available`
2. Backed up `~/honcho/.env` → `~/honcho/.env.backup-pre-embedding-fix-20260807-104855`
3. Appended to `~/honcho/.env`:
   ```
   LLM_OPENAI_API_KEY=<openrouter_key>
   EMBEDDING_MODEL_CONFIG__OVERRIDES__BASE_URL=https://openrouter.ai/api/v1
   ```
4. Force-recreated containers: `docker compose up -d --force-recreate api deriver`
5. Verified env vars loaded inside container
6. Confirmed fix: `POST /messages` → HTTP 201 ✅

### Rollback

Delete the two lines added to `.env`, run `docker compose up -d --force-recreate api deriver`. ~30 seconds.
