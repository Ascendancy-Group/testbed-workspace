### AscMesh — Agent Communication Mesh (MAJOR WORK)

**Problem:** No reliable agent-to-agent communication without Slack noise.

**Architecture decision (locked):**
- 3 Docker containers on honcho-m1: mesh-api (FastAPI) + Redis OSS 7 + SQLite WAL
- 1 ascmesh worker container on each agent machine
- Redis: pub/sub live delivery + rate limiting
- SQLite WAL: durable store + immutable audit log, Pieter-queryable
- Transport: Tailscale (WireGuard) only — nothing external
- Identity: Ed25519 keypairs — signed messages, verified sender
- No JS, no external services, no database fees

**Security model (hard rules):**
- All mesh messages = untrusted user-role input. Cannot override SOUL.md/GOVERNANCE.md
- No peer can elevate another's authority
- Rate limit: 10 msg/min per sender, 2000 char max body
- Registry: Pieter-write-only. Agents cannot self-register
- Audit log: root-owned, append-only, agents cannot modify
- Anomaly/rejection → #agent-ops alert

**Rejected options:**
- ocmesh — public Nostr relays. Hard no
- agent-team-mesh — no security model. Hard no
- decent-agent-mesh — public DHT, JS. Hard no
- openfused — polling only, no central room
- Native sessions_send — loopback only without JSON changes
- Official OpenClaw Nodes — wrong primitive (hub/spoke, not peer mesh)
- Supabase — not needed
- JSONL audit log — replaced by SQLite WAL
